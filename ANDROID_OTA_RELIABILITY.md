# 64: расследование первого OTA bootstrap timeout

Дата: 16 октября 2026. Исходники: `93a57cf695ec405019389c47687a3409d0aace4b`,
ветка `feat/android-ota-64`. Итог: **BLOCKED для stable OTA**.

## Вывод

Причина исходного timeout `.1` не доказана. В новой серии ошибка не воспроизвелась,
в том числе при первой активации исходного immutable ZIP `.1` на чистом профиле
подписанной APK, сразу offline. Поэтому нет основания объявлять `.2` исправлением.
Продуктовый код, настройки readiness, native code и timeout 30000 ms не изменены.

`.2` в наблюдавшихся запусках успешно загрузила assets, запустила приложение,
восстановила состояние и получила native readiness acknowledgement. То же произошло
с `.1`. Это объясняет результат отдельных прогонов, но не различие с первым сбоем.

## Финальная проверка QA/CDN: 17 октября 2026

Проверка завершена в **07:22:07 МСК / 04:22:07 UTC**. Ничего не публиковалось:
использованы только GET-запросы и public key. Приватные ключи не читались.

Сначала получен файл через GitHub Contents API (HTTP 200), затем три публичных

срок действия, sequence **1792184090312**, enabled=false и отсутствие release.
Тело каждого публичного ответа побайтово совпало с файлом из Contents API.

Общие заголовки: `Cache-Control: max-age=300`,
`Content-Type: text/plain; charset=utf-8`, `Access-Control-Allow-Origin: *`.

`9c450db37d7c4728eeb67895b728bf1dd355ad28f056359b3e39ca1695060e7d`.

HTTP с Android User-Agent не выдаётся за новый запуск реального WebView/Samsung.
Эти запросы проверяют доступный с данного компьютера CDN, не все PoP одновременно.

Канал больше не предлагает новую загрузку клиенту, получившему этот подписанный
manifest. Добавлены три узких regression-теста: автоматическая проверка pause,
ручная проверка pause и сохранение ранее подготовленной очереди. В первых двух
не вызываются recordAttempt/download/queue/set/reset; статус клиента paused.

**Граница pause:** это не revoke и не удаление ZIP. Уже скачанный и поставленный
в очередь пакет может активироваться при cold start; клиент с pending сначала
обрабатывает свою очередь. Offline-клиент или другая CDN-копия узнает о pause
только после получения актуального manifest. Immutable ZIP остаются доступными
по своим адресам. Мгновенная отмена всех ранее подготовленных обновлений не заявляется.

Новые проверки: **32/32** OTA/crypto/compatibility tests, Oxlint PASS,
TypeScript frontend PASS, compatibility fingerprint прежний. Runtime-28,
native-13, полный frontend/Worker и сборки повторно не запускались: изменены
только тест и доказательства, код приложения и native code не менялись.
HTTP-статусы, времена, выбранные headers, публичный signed envelope и ограничения
сохранены в `ota/qa-pause-verification-64.json`. Секретов и пользовательских данных
в этом файле нет. Перед commit выполнен `git diff --check` и аудит состава файлов.

Итог остаётся **BLOCKED**: распространение pause подтверждено, но исходная причина
