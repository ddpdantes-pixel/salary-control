# Сохранение плана активного таймера

Решение PO от 1 ноября 2026: активный сеанс продолжает исходный план; новый запуск
использует новый порядок. `gymPlanVersion: 1` закрепляет 90/90 → Переход → Бабочка →
Фигура 4 → Поза ребёнка. Версия 2 закрепляет Поза ребёнка → Фигура 4 левая →
Фигура 4 правая → Бабочка → 90/90. Обе длительности: 300/60/60/120/300 секунд.

Сеанс официальной 1.1.0 без версии однозначно относится к плану 1. При чтении
добавляется версия 1; существующее сохранение контроллера записывает её в тот же
ключ. stageIndex, completedStages, timestamps, pausedRemainingMs и dateId сохраняются.
Названия в UI/уведомлениях, переходы и остаток времени используют план сеанса.
Новый gym всегда создаётся с версией 2. Таймер лица не меняет план/формат.

Продуктовые QA-кандидаты с новым порядком без версии не публиковались. Их локальные
синтетические сеансы не являются новым production legacy-форматом. Не выводить план
из текущего stageIndex, времени установки или даты устройства.

Неподдерживаемая версия, недопустимые индексы/остатки/даты или повреждённый JSON
останавливают только optional timer session. Контроллер показывает сообщение об
остановке; HealthState/история/индивидуальные галочки/настройки здоровья не меняются.
Версия 1 и 2 завершаются с manual completion, без автоматических gym-отметок.

При восстановлении пропущенные события обрабатываются без воспроизведения звуков.
После сохранённого перехода повторный mount не воспроизводит этот переход заново.
Пауза сохраняет остаток независимо от прошедших дней, running сохраняет абсолютный
deadline; переход через полночь не заменяет дату начала сеанса.

Новые сеансы плана 2 сохраняются в отдельном optional ключе
`moi-ritm.active-gym-timer.v2`. Старый builtin читает только прежний v1-ключ и потому
не показывает новый stageIndex под старым названием. При cold-start переходе к builtin
новый сеанс сохраняется на паузе с текущим остатком; фоновая проверка revoke его не
прерывает. При возвращении совместимого JS план 2 восстанавливается из отдельного ключа.
Если в builtin начат другой сеанс, его v1-запись имеет приоритет; сохранение выбранного
сеанса удаляет второй optional ключ. Stop/completion очищают оба ключа. Это один активный
таймер, а не два параллельных таймера. HealthState/backup/настройки не меняются.
При ошибке optional storage pause — best effort; security reset не блокируется таймером.
Публикация и физическая Samsung-приёмка остаются отдельными gates.
