## 1. Пока ничего не удалять с Samsung

Не удаляйте установленный debug APK и старую PWA. Не очищайте данные приложения.
Не пытайтесь обновить debug APK файлом с другим сертификатом: Android отклонит
обычное обновление при несовпадающей подписи. Смена versionCode этого не исправляет.

Сначала в действующем debug APK:

1. Откройте «Зарплата → История → Облачная копия».
2. Нажмите «Сохранить в облако» и дождитесь сообщения об успехе.
3. Обновите список копий. Проверьте дату, время и наличие новой копии.
4. Нажмите «Сохранить резервную копию в файл». Сохраните JSON в «Загрузки» либо
   другое место вне приватных файлов приложения. Проверьте файл через «Мои файлы».
5. Откройте «Перенос на новое устройство» и сохраните ключ подключения в своём
   защищённом месте, доступном после удаления приложения.
6. Убедитесь, что и JSON, и ключ доступны вне «Моего ритма». Ключ не отправляйте
   в чат, Git, публичные логи или скриншоты.

Если копия не сохраняется, отсутствует в списке или ключ не сохранён — остановитесь.
Наличие старой копии PWA не заменяет свежую копию текущих Android-данных.

## 3. Воспроизводимая release-сборка

В локальном PowerShell выполните одну команду. Она работает из любой папки:

```powershell
& 'C:\Users\User\OneDrive\Документы\salary-control\scripts\build-android-release.cmd' -PrepareUpdateTest
```

Запускатель использует уже установленный PowerShell 7 без изменения execution policy.
Он нужен, потому что Windows PowerShell 5 на этом ПК запрещает запуск скриптов;
обходные флаги и изменения системных настроек не применяются.
Скрипт сам находит установленные JDK 21, SDK 36 и Node, проверяет наличие ключа
и один раз спрашивает пароль через `Read-Host -AsSecureString`. Не включайте
transcript, запись экрана, вывод окружения или Gradle `--debug`/`--info`.
Пароль не входит в команду, историю, файлы или вывод скрипта. Credentials добавляются
только в окружение дочерних keytool/Gradle, а не в глобальное окружение PowerShell.
Ссылки на временные секретные значения очищаются в finally; это не обещание защиты
от администратора/вредоносного ПО или полного стирания управляемой памяти.

Проверяются PKCS12, private-key entry alias `moyritm`, публичный сертификат, RSA 3072,
действительность и исходный срок 25+ лет. Пароль keytool передаётся через
`-storepass:env`, не аргументом-значением. Для стандартного созданного PKCS12 один
введённый пароль используется как storePassword и keyPassword; успешная подпись
проверит возможность работы именно с этой комбинацией.

После одной сборки assets и Capacitor sync создаются QA N, QA N+1 и затем обычная
2 / 1.0.0. Каждый APK проверяется apksigner, сравнивается сертификат с keystore,
проверяются пакет, версия и отсутствие debuggable. Gradle получает
`--no-daemon --no-configuration-cache`; signing-вывод не сохраняется в лог и
не перепечатывается целиком. При ошибке показываются этап и понятное сообщение.

QA APK и отчёт только с публичными метаданными сохраняются в новой подпапке
`android/app/build/outputs/moyritm-release-checks/`. Отчёт `verification.json`
имеет статус `SIGNED_BUILDS_ONLY_RUNTIME_CHECK_PENDING`: он ещё не означает
проверку обновления или приёмку на Samsung. Никаких adb/install/uninstall в скрипте нет.

Когда появится «Готово», сообщите Codex только: **«Скрипт завершился»**.
Пароль повторять или присылать не нужно. Далее Codex использует готовые QA APK
для проверки обновления на эмуляторе; секрет ему для этого не нужен.

Для будущей обычной сборки без подготовки двух QA APK используйте ту же команду
без `-PrepareUpdateTest`. Инженерный `pnpm run android:release` также остаётся
доступным для уже настроенного защищённого окружения процесса.

Файл после успешной сборки:
`android/app/build/outputs/apk/release/app-release.apk`.
Его наличие само по себе не доказывает актуальность: проверяйте BUILD SUCCESSFUL,
дату сборки, package, версию и сертификат. Не путайте файл с app-debug.apk.

## 4. Проверки до передачи APK пользователю

Эти проверки выполнены в задаче 63; доказательства и ограничения описаны
в `ANDROID_RELEASE_VERIFICATION.md`. Для последующих сборок повторяйте проверки:

- Проверяет реальный release build и `apksigner verify --print-certs`.
- Сравнивает SHA-256 сертификата APK с сертификатом созданного keystore, проверяет
  срок действия, package и версию; фиксирует публичный fingerprint, путь и размер APK.
- Проверяет, что release не debuggable, не использует debug-подпись и не содержит
  локальных тестовых серверов/секретов. WebView debugging в Capacitor по умолчанию
  зависит от Android debug-флага; release явно имеет `debuggable false`.
- На отдельном эмуляторе, не Samsung пользователя, проверяет release N → N+1
  с той же подписью, синтетическими localStorage/IndexedDB и отдельным тестовым
  облачным подключением. Проверяет его сохранность и offline-запуск.
- Повторяет необходимые regression/build проверки и только после успеха делает
  один логический коммит задачи 63. Main и GitHub Pages не меняются.

Для QA доступен Gradle-параметр `-PmoyritmTestVersionCode=2`, затем `=3`.
Имена версий автоматически становятся `1.0.0-qa.2` и `1.0.0-qa.3`.
Параметр не меняет version.properties и не создаёт новый ключ. QA APK сохраняются
отдельно и **никогда не передаются на Samsung как постоянный релиз**.
После QA заново собирается обычная согласованная версия 2 / 1.0.0 без параметра.
В текущем результате она проверена отдельно: 3 456 998 байт; тестовые версии её
не подменяют. Официальную APK установили в ещё один пустой тестовый эмулятор.

## 5. Когда можно удалить debug APK

Только когда одновременно выполнены все условия:

- Подписанная release APK проверена и доступна на телефоне вне старого приложения.
- Пользователь подтвердил свежую облачную копию и сохранённый вне приложения ключ.
- Локальный JSON доступен как дополнительная страховка.
- Резервные копии постоянного signing keystore и пароль сохранены.
- Старую PWA не удаляли.

После этого пользователь самостоятельно удаляет debug APK через настройки Samsung.
**Это удалит его приватные localStorage и IndexedDB. Codex не запускает uninstall
или очистку данных телефона.** До выполнения перечисленных условий удалять нельзя.

## 6. Установка и восстановление на Samsung Galaxy S26

1. Через «Мои файлы» откройте проверенную release APK и разрешите установку из
   выбранного источника, если Android запросит. Не используйте QA/debug APK.
2. Откройте «Мой ритм → Зарплата → История → Облачная копия».
3. Откройте существующий перенос на новое устройство и введите сохранённый ключ
   подключения лично, не передавая его Codex.
4. Обновите список копий. Выберите копию по проверенным дате/времени, а не просто
   первую попавшуюся: старые PWA/Android-копии могут отличаться.
5. Откройте preview, проверьте состав и подтвердите восстановление.
6. Сверьте зарплату и продажи, фактические финансы/обязательства, цели с изображениями,
   здоровье/историю/обучение, настройки, Кубышку и доступ к хранилищу паролей.
7. Закройте/откройте приложение и перепроверьте данные. Затем создайте новую
   облачную копию уже из release и проверьте её наличие.
8. PWA оставьте до окончательной сверки и подтверждённой резервной копии.

Если облако недоступно, используйте «Восстановить из файла» с локальным JSON,
preview и явным подтверждением. Если restore не удался — не очищайте приложение,
не удаляйте копии и не записывайте пустое состояние поверх нужной облачной копии.
Сохраните текст ошибки без секретов и продолжите диагностику; PWA остаётся страховкой.

## 7. Что входит в backup

Используется прежний формат v10 без изменений: зарплата/продажи, FinanceState,
HealthState и настройки, история/обучение/долги, Кубышка, настройки уведомлений,
зашифрованное хранилище паролей и изображения финансовых целей.
Пароль хранилища паролей остаётся прежним; backup его не заменяет.

Скриншоты тренировок из отдельного attachment-хранилища в backup не входят.
В задаче 63 пользователь принял отдельный рабочий сценарий: вечерний текст
копируется в ChatGPT, скриншоты при необходимости прикладываются отдельно.
Поэтому это **известное принятое ограничение**, а не повод менять backup или share.
Нужные оригиналы изображений пользователь сохраняет отдельно до удаления debug APK.
Apple Health sync secret также не экспортируется прежним контрактом.

## 8. Последующие обновления

Меняйте только публичные versionCode/versionName в `android/version.properties`:
versionCode каждой следующей пользовательской APK должен быть больше предыдущего
установленного релиза. Например, после 2 / 1.0.0 — 3 / 1.0.1.
Собирайте с **тем же** package ID, origin и постоянным signing key.
Проверяйте сертификат и устанавливайте поверх release, без удаления приложения.
Перед обновлением всё равно делайте свежий backup.

Не копируйте signing credentials в gradle.properties, build.gradle, .env или Git.
Не меняйте alias на новый ключ и не создавайте новый keystore ради обновления.
Не публикуйте debug/release APK в публичном GitHub Release в рамках этой задачи.

Официальные источники:
- https://developer.android.com/studio/publish/app-signing
- https://developer.android.com/studio/publish/versioning
