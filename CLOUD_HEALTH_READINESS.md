# Облачные копии и компактный экран здоровья

База: принятый `168652f` (stable web 1.2.1, native APK 1.2.0/code4). Работа изолирована в `codex/cloud-health-simplification`. Production Worker, main, AI, stable и QA не публикуются без нового GO этого задания.

## Подтверждённая диагностика

- В прежнем интерфейсе успешный POST и следующий GET были одной операцией с общим catch: ошибка списка объявлялась общим сбоем. У fetch/response.json и подготовки payload не было срока ожидания.
- 28 ноября настоящий production API успешно принял отдельный синтетический набор, шестую копию около 543 КБ, скачивание и повтор того же id; оставалось пять версий. Доступность не выводилась из локального индикатора подключения.
- На другом отдельном синтетическом ключе воспроизведён дефект production-ротации: пять будущих createdAt, затем шестой POST201 с текущей датой → GET этой копии404. Новый снимок удалялся по клиентской дате сразу после подтверждения.
- Конкретные старые попытки Samsung и его пять личных версий не читались; пользовательский ключ не извлекался и не сбрасывался. Административные логи/D1 deployment metadata недоступны: локальная CLI-сессия Cloudflare не авторизована. Нельзя приписать каждую пользовательскую ошибку одному из дефектов или только сети телефона.

## Исправление клиента

Новый `cloudBackupService.ts` ограничивает полное ожидание HTTP, включая тело ответа, 20 секундами и отменяет запрос. Подготовка payload ограничена 15 секундами. Точный неподтверждённый запрос сохраняется до отправки в отдельной IndexedDB `moi-ritm-cloud-pending-v1`; cloud key там не дублируется. При неизвестном исходе проверяется тот же id и checksum, при отсутствии повторяется тот же снимок с тем же id. Перезагрузка не превращает его в новую слепую отправку. Нельзя POST без успешно сохранённого локального запроса. Повреждённый pending не отправляется и не удаляется молча.

После POST-подтверждения дата/размер обновляются сразу. Ошибка списка даёт статус «Копия сохранена. Не удалось обновить список», а неизвестное число версий обозначается «—». Устаревшая начальная загрузка списка не перекрывает более новое подтверждение. Повторное нажатие коалесцируется. Локальный JSON-экспорт доступен независимо от ожидания облака. Даже повреждённая существующая запись ключа не заменяется новым ключом автоматически.

`src/cloudBackup.ts` закреплён в native fingerprint установленной APK, поэтому его формат/ключи и байты не меняются. Живой облачный экран использует безопасный адаптер, экспортирующий прежние key/format helpers. Native baseline не переписывается. Новое хранилище pending отдельно от пользовательских баз и существующих схем; старый код при откате его игнорирует.

## Worker

Таблицы и migrations остаются прежними. Новая дата подтверждённого снимка берётся на сервере. Ротация внутри одной D1 batch-транзакции всегда сохраняет только что записанный id плюс четыре предыдущих по stored_at/rowid; будущие клиентские даты больше не удаляют новый снимок. Идентификатор снимка неизменяем: повтор того же содержимого возвращает прежнее подтверждение без новой ротации, иное содержимое с тем же id получает409. Конкурирующий повтор безопасно проверяется после отказа INSERT. Сбой chunks откатывает batch и сохраняет пять прежних рабочих копий.

Диагностика ошибок не журналирует ключи, payload или SQL bindings. Существующие auth/CORS/размеры/rate limit не отключаются.

## Здоровье

- Диагностика задолженностей, экспорт исходных строк и восстановление находятся в закрытом пункте «Настройки → История и восстановление». Исходные копии и критические блокирующие сообщения сохраняются.
- Вместо ежедневного загрузчика — одна жирная строка «Не забудьте скриншоты тренировки и пульса». Существующие вложения читаются для истории/отправки; IndexedDB не чистится. Отправка ждёт вложения правильной выбранной даты.
- У растяжки убраны постоянные инструкции и переключатели. Native start, legacy adoption и resume получают sound/vibration=true. Параметры таймера лица остаются прежними. При ошибке изменения сигналов живой таймер не скрывается. «Проверить звук», время, этапы и управление сохранены; реальные ошибки остаются видимыми.
- Удалён постоянный абзац под отправкой в ChatGPT. Завершение дня и оба режима отправки остаются прежними.

Нативные Java/Kotlin, bridge, manifest, package ID, Android-подпись и APK не меняются. Пять сигналов 05:00/06:00/07:00/09:00/14:00 и 14-минутный план сохраняются. Предыдущая реальная native-приёмка не заменяет новой физической Samsung-проверки; её результат здесь не заявляется.

## Проверки и выпуск

Адресные тесты, настоящий production API на синтетике, HTTP→локальный Worker/D1 с потерей ответов и 20-секундным зависшим телом, браузерный production POST/GET и JSON-скачивание, widths360/390/430×light/dark, screenshots/overlay фиксируются в `ota-output/cloud-health`. Реальная SQLite/D1 batch-ошибка также проверяется на сохранность предыдущих копий. Облако не принимается только по mock-тестам.

Готовится локальный подписанный QA OTA `1.2.2-qa.cloud-health.3` только для native4. Worker имеет отдельный dry-run bundle. Финальные commit, подписи, hashes и точные ограничения приёмки находятся в `ota-output/cloud-health/REPORT.md`. Production пока остаётся прежним.

После одного явного GO: авторизация в существующем аккаунте Cloudflare, независимый защищённый export D1 до изменений, проверка ожидаемого deployment и возможность возврата прежнего Worker; публикация Worker без замены DB/секретов и реальный синтетический smoke; штатная интеграция принятого commit в clean main, сборка/проверка свежего stable1.2.2, сохранение revocations и атомарная публикация указателя. Без Cloudflare-доступа Worker не публикуется. Новое ТЗ не требуется.
